# Assurance experiment protocol

- Protocol id: `veriforge-assurance-v1`
- Protocol version: `1.1.0`
- Software version under test: `1.0.0` (not bumped)
- Generator seed: `20261011`
- Dataset version: `1.1.0`
- Historical held-out partition: `datasets/held_out` (8 cases, version `0.5.0`) is not overwritten and is not the scoring set for this protocol.

This file is hashed before any held-out oracle label from dataset `1.1.0` is inspected. The hash and creation time live in `research/protocol_preregistration.json`. Do not edit this file after that hash without recording an amendment.

## Research questions

Primary question H_audit: On the new held-out pairs, does the production Z3 path plus an independent Z3 encoder reject non-equivalent rewrites that a single production path would accept, without increasing false rejections of equivalent rewrites?

Secondary question H_test, which this environment can execute without Z3: On held-out pairs whose oracle label is non-equivalent, is the false-equivalence rate of the boundary-plus-random testing baseline at budget 10,000 strictly lower than at budget 10?

H3_exec, distinct from the historical H3: Across the preregistered scaling grid, is the Spearman correlation between operator count and median independent-evaluator execution time strictly positive? Historical H3 (solver overhead by category) stays unresolved if solver timings are unavailable.

## What was fixed before this hash

A development-only oracle check, which did not score held-out families, found that in unsigned width 1, `x + y` equals `x - y` and `x - y` equals `y - x`, because negation is the identity in the ring of integers modulo 2. Those development cases in families `op_swap` and `swap_sub` were relabeled `mode_dependent` before this protocol was hashed. Held-out families were not rewritten from held-out outcomes. One development factoring case at width 8 with three variables exceeds the exhaustive budget; its algebraic intent remains `equivalent` and the oracle may return `not_computed`.

## Units, inclusion, and partitions

The independent experimental unit for confirmatory rates is the expression pair, clustered by transformation family. Families are not split across partitions.

Held-out families, entire families only:

- `distributivity`
- `sub_self`
- `const_off_by_one`
- `modular_collapse`
- `nested_identity`
- `wrong_factor`
- `unsupported_syntax`

All other families are development. Development may be used to debug. Held-out pairs are not used to choose thresholds, rules, or budgets. There is no numeric threshold to tune. The testing budgets are the four values below.

Supported operators are binary `+`, `-`, `*`, unary `+` and `-`, integer literals, and variables. Mode A is unbounded integers. Mode B is unsigned wrap at the case width. Literals outside `[0, 2^w - 1]` are invalid and are not reduced.

## Label source

Construction intent is not the ground-truth label.

- Mode B: exhaustive independent evaluation when `2^(w*k)` is at most `65536`. Otherwise `not_computed`. A sample is never called exhaustive.
- Mode A: polynomial identity within a term budget of `4096`, with a concrete witness re-evaluated by the independent evaluator when the polynomials differ.
- Parse failures: `unsupported` or `invalid_input` from the independent parser.

Pairs labeled `not_computed` are excluded from accuracy denominators and counted in coverage. Metrics that need a class use the oracle label.

## Baselines

1. Production Z3 verifier. This script does not invoke it. If `z3` is not importable, the baseline is `unavailable`.
2. Production verifier plus its existing counterexample validator. Same availability rule.
3. Audited pipeline as implemented by `combine_gates` over the completed polynomial or exhaustive gate, with SMT gates marked `unavailable`. Agreement with the oracle on tractable cases is a contract check, because the establishing method is that oracle. It is not an independent estimate of SMT accuracy.
4. Rule-only baseline: the four production identity rules applied syntactically, with no SMT call. Prediction `equivalent` only when both sides reduce to the same rendered term. Otherwise `not_handled` (abstention, not a rejection).
5. Exhaustive oracle for tractable Mode B pairs. This is the label source for those pairs.
6. Seeded mutants in `veriforge/semantic_mutants.py`, scored on the fixed fixtures in `run_mutants`. Denominator is the number of mutants whose semantic effect is observed. A mutant that does not change behavior is not counted as a detected fault.
7. Testing baseline at budgets 10, 100, 1,000, and 10,000. Boundary pool: for Mode A, `{-2,-1,0,1,2}` and neighbors; for Mode B, `0, 1, 2, 2^w-1, 2^(w-1), 2^(w-1)-1` and neighbors that lie in `[0, 2^w-1]`. The value `-1` is not wrapped into Mode B. Remaining draws are deterministic from `seed = 20261011 + case_index * 10 + budget`.

CVC5 and Bitwuzla are attempted only as import or binary checks. If they are absent, no comparison number is reported.

## Decision rules

H_audit: `inconclusive` when the production SMT arm is not executed. It is not `not_supported` and not `supported`.

H_test: among held-out pairs with oracle label `non_equivalent`, let `r(n)` be the fraction not distinguished by the testing baseline at budget `n`.

- `supported` if `r(10000) < r(10)` and both denominators are at least 30.
- `not_supported` if `r(10000) >= r(10)` and both denominators are at least 30.
- `inconclusive` if either denominator is below 30.

Wilson 95% intervals are descriptive. Overlap does not change the point-estimate decision.

H3_exec: `supported` if Spearman rho between operator count and median execution time on the scaling grid is strictly positive; `not_supported` if rho is less than or equal to zero; `inconclusive` if rho is undefined. This does not settle historical H3.

A reported category with fewer than 30 pairs is `insufficient_sample` and is excluded from per-category conclusions.

## Scaling grid

Mode B widths 8, 16, 32, and 64; nesting depths 1, 2, 4, and 8; variable counts 1, 2, and 3. Three untimed warmup evaluations, then 30 timed evaluations of one assignment. Solver time is a separate field and is `unavailable` when Z3 is absent. Bootstrap median interval uses 2,000 resamples and seed `20261011`.

## Mutant fixtures

The ten mutants `m01` through `m10` are scored by the detectors named in `MUTANTS`. Detection on a fixture is not a population mutation score.

## Stops

One held-out scoring run after this hash. If a code change follows inspection of held-out labels, that run is exploratory unless a new protocol hash and a new held-out seed are used.

## Reproduction

```bash
python3 scripts/run_assurance_experiment.py
```

The command exits without scoring if `research/protocol_preregistration.json` does not match the SHA-256 of this file.
